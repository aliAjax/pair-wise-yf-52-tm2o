# pair-wise-yf-52 戏剧排练台词版本与舞台提示管控

## 源提示词摘要
导演、编剧、舞台监督和演员共同维护不同版本的剧本、角色台词、上下场提示、道具与灯光音效提示。编剧提交后需逐条合并，演员可查看最新版并标记疑问；支持版本对比、单条采纳、批注、冲突处理、排练模式、大字号提词和断网缓存。

## 技术栈
Angular + TypeScript + Angular Material + NgRx + Angular Router + RxJS + Angular CDK + Transloco。

## 已实现闭环
- 剧本版本和导演修订的创建、切换与版本差异摘要。
- 角色台词、舞台提示的采纳、退回和待确认状态。
- 排练模式、在线/离线切换与 localStorage 持久化。
- 未确认内容保留在草稿版本中，不会自动混入已采纳版本。

## 演出运行台（开演冻结）

顶部切换到「演出运行台」。针对“导演临场删台词/换场序，只能口头通知，灯效按旧顺序执行”的问题：

- **冻结运行版**：冻结后角色台词与舞台提示分别拥有独立执行顺序（台词 `L#`、提示 `Q#`），各自连续编号。
- **换序以版本为准**：导演临时改动先进入草稿，舞台监督确认后产生 v2、v3…。确认时
  - 旧版本中**未执行**的舞台提示一律标记 `VOID` 作废并重算顺序；
  - **已执行**的提示永久保留在其落锤的旧版本中（不复制、不改写）；
  - 新版本沿用“血缘号”承接仍在使用的提示，回到待执行并重新编号；导演新增的提示分配新血缘。
- **设备回执按设备序号对齐**：灯光 `LIGHT-01`、音效 `SOUND-01`、场务 `STAGE-01` 各自维护单调序号（#1、#2…）。
  - 离线时回执先进本地 outbox 且照常计序；网络恢复后从已合并断点（`syncedSeq`）之后按序续传；
  - 同一设备序号重复到达（链路重发）只算一次（`DUP`）；
  - 指向已作废/旧版本提示的**迟到回执**只登记为 `LATE_STALE`，绝不盖到新顺序上；
  - 序号缺号（`GAP`）拒绝并保留队列，等待缺口补齐；演出结束后新回执一律拒绝。
- **岗位视角隔离**：场务台（STAGE）永远看不到灯光口令；各设备台只看本岗位提示；舞台监督看全部。
- **演出后可查**：结束后运行版只读封存，顶部版本页签可逐版本查看每条提示的执行状态、落锤设备序号与时间、设备台账与监督台日志（localStorage 持久化）。

核心规则为无框架依赖的纯函数（`src/app/runbook/runbook.logic.ts`），可脱离浏览器验证：
```bash
npm run test:logic
```
